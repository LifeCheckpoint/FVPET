# FVP 剧情编辑器 —— 需求边界 · 工作流 · UI 设计

> 文档状态：Architect 产出，是 [`fvp-hcb-editor-plan.md`](plans/fvp-hcb-editor-plan.md:1) 的补充设计文档。
> 目的：在动手写 UI 之前，把"做/不做、怎么编辑、长什么样"三件事钉死，防止功能臃肿四不像、辣眼 UI、莫名其妙的编辑流程。

---

## 0. 一句话定位

> **只做 FVP 剧情脚本的可视化创作、验证与预览工具。**

它不是游戏引擎，不是资源工厂，不是项目管理平台。

---

## 1. 目标用户（已拍板）

**原创 FVP 剧本作者为主**，核心诉求是"创作新剧情"：

- 选角色 / 加背景 / 配立绘 / 配 BGM / 写选项，全部在编辑器内完成。
- 资源表（角色、背景、音频）**可编辑**。
- **底层细节完全隐藏**：用户永远不接触 opcode、CFG、栈机、重定位、raw 字节。UI 不提供 opcode 反汇编视图、不提供 raw 块内部编辑。

推论（写入验收）：

- `raw` 节点在 UI 中渲染为**只读占位块**（"未识别的演出块 · 尺寸 N 字节"），不可编辑内部，仅可整体删除或保留。
- 资源视图从"只读表格"升级为"**可编辑资源管理器**"。
- 需要"**新建工程向导**"（选底座游戏 → 定 NLS/分辨率/标题 → 生成空剧情骨架）。

---

## 2. 需求边界（防臃肿）

| 维度 | 做（核心闭环） | 不做（明确拒绝） |
|---|---|---|
| 节点类型 | `speak / dia / bsset / bgset / selset / audio / branch / thread / label / jump / comment`（`raw` 为只读占位） | 不做动画时间轴（Dissolve/Motion 一律 `raw`） |
| 编辑能力 | 增删改、拖拽、连线、undo/redo、编译/反编译、验证 | 不做 if/while 可视化编程（分支仅 `selset` + `branch`） |
| 资源管理 | 角色/背景/音频表可编辑，新增条目自动生成对应模板函数 | 不做画图、音频剪辑、图像处理 |
| 预览 | 文本、立绘位置、背景、选项、G[] 面板、label 断点 | 不做引擎级粒子/视频/物理模拟 |
| 平台 | 单机单工程 | 不做多项目、云同步、协作、插件市场 |

## 3. 编辑范式与工作流

### 3.1 编辑范式（已拍板）

**流程图为主 + 可切换的『剧本文本视图』**：

- **流程图**是唯一编辑面，一切增删改都在图上发生。
- **属性面板**是选中节点的表单投影（右侧），不是第二编辑入口。
- **剧本文本视图**是 IR 的**只读投影**，形似 Ren'Py 脚本，用于快速校对大段台词；不可编辑，点击文本行可定位回图中对应节点。

### 3.2 唯一主工作流

```text
新建工程（选底座游戏）→ 流程图加节点/连线 → 属性面板填字段 → 预览验证 → 编译导出 .hcb
```

### 3.3 视图纪律（四视图关系）

| 视图 | 性质 | 作用 |
|---|---|---|
| 流程图 | **可编辑** | 唯一编辑面，主视图 |
| 属性面板 | 可编辑（表单投影） | 编辑选中节点字段 |
| 剧本文本视图 | 只读投影 | 快速校对台词、看全剧节奏 |
| 时间线 | 只读投影 | 沿当前路径线性化，校对节奏 |
| 预览 | 只读（但可驱动推进） | 真实/假引擎画面 + G[] 面板 + label 断点 |
| 资源管理器 | **可编辑** | 角色/背景/音频表维护 |

## 4. 剧本文本视图 DSL 形态（只读投影初稿）

由 IR 投影而来，**不可编辑**。示例：

```renpy
# 剧本投影（只读）
label start
    speak クロ "今天的风很大。" voice 123
    bg 教室
    bs クロ pose 1 costume 2 face 0 at l
    dia "……"
    sel:
        "去学校" -> go_school
        "回家" -> go_home
    bgm 3
    jump go_school
```

投影规则：

- `speak 角色 "台词" [voice n]` ← `speak` 节点
- `bg 名称 [variant n]` ← `bgset` 节点
- `bs 角色 pose n costume n face n at {l|m|r}` ← `bsset` 节点
- `sel:` 块 ← `selset` 节点
- `bgm n` / `se n` ← `audio` 节点
- `label x` / `jump x` ← `label` / `jump` 节点
- 点击任意一行，流程图中对应节点高亮并滚动到视野内。

## 5. 资源表可编辑（新增能力）与底座游戏机制

### 5.1 关键现实约束

FVP 的 SPEAK/bgset/bg 切换等"演出能力"不是引擎标准库，而是**每个游戏自己的 HCB 函数库**（如 [`hcb_build.py`](.reference_repo/SImple-.hcb-Editor/hcb_build.py:20) 的 `bg_list` 与 [`cha_list`](.reference_repo/SImple-.hcb-Editor/hcb_build.py:215) 指向原版函数地址）。因此：

- **原创工程必须基于一个"底座游戏"**（如 sakura），继承其函数库、syscall 导入表、分辨率等——对应编译上下文的 `patchBase?: HcbBinary`。
- 底座游戏提供**已有角色/背景**的函数地址映射。
- 编辑器"添加新角色/新背景"时，编译器用**模板生成函数定义体**（而非仅生成调用点）。

### 5.2 模板系统升级：`instantiate` 的两种形态

原计划 §5.2 的模板只生成"调用点"，需补充"**函数定义体**"形态：

```ts
export interface Template<N extends IrNode = IrNode> {
  id: string;
  signature: AsmPattern[];
  slots: Record<string, SlotSpec>;
  instantiate(node: N, ctx: TemplateCtx): AsmBlock[];        // 调用点
  emitFunctionDef?(resource: ResourceEntry, ctx: TemplateCtx): AsmBlock[]; // 函数定义体（新增资源时）
  test: GoldenTestSpec;
}
```

以 SPEAK 为例：34 份模板结构相同（216 字节），`styleIndex`（G[227]）与 `emotionCounter`（G[2000+styleIndex]）随角色递增。新增第 35 个角色 = 用 `emitFunctionDef` 生成第 35 份 SPEAK 函数（替换名字字符串与 styleIndex，其余骨架照抄），编译器在 `layout`/`relocate` 阶段为其分配地址并注册函数引用。

### 5.3 资源管理器三张表

| 表 | 字段 | 新增资源时编译器的动作 |
|---|---|---|
| 角色 | 名称、别名、SPEAK 函数地址（底座已有）/ 自动分配（新增）、立绘槽（pose/costume/face 编号） | 用 `fvp.speak` 模板生成新 SPEAK 函数定义体 |
| 背景 | 名称、变体、背景函数地址 / 自动分配 | 用 `fvp.bgset` 模板生成新背景函数定义体 |
| 音频 | BGM 编号、SE 编号、语音编号 | 仅数据（syscall 编号直传，无函数生成） |

## 6. UI 设计原则（落实 ui-aesthetics）

- **视觉主题**：`quiet precision`（安静精确）工具型界面，参考 Figma/Blender 的克制专业感。**提供深色（默认）与浅色两套主题**，共享同一套设计 token（中性色阶 + 单一冷色 accent）；浅色不引入米白/暖白，保持与深色同等的克制。
- **布局**：三栏——左（节点调色板 + 资源管理器）｜中（流程图主画布，占据最大面积）｜右（属性面板 / 预览 / 剧本文本切换）。
- **色彩纪律**：中性冷灰为主；单一冷色 accent 只用于"选中节点"与"未保存脏标记"；**不给每类节点涂不同色**，节点差异靠图标 + 文本层次表达。
- **节点卡片紧凑**：`speak` 节点仅"角色名 + 台词截断"两行，其余字段进属性面板；卡片默认安静，hover 微抬升，selected 用 1px accent 描边（区别于 hover）。
- **深度克制**：阴影只用于画布节点抬升与面板分层；不做雾状光晕、不做霓虹渐变。
- **预览面板保持游戏原始比例**（4:3 / 16:9），四周留边，不自作聪明拉伸铺满。
- **状态纪律**：默认安静 → hover 微反馈 → selected 清晰 → 未保存脏标记明确；空状态（新工程）有引导文案但不啰嗦。
- **界面语言**：中文（默认，可扩展 i18n 但不优先做）。
- **设置界面**：统一管理编辑器偏好——主题（深/浅）、界面语言、默认 NLS（sjis/gbk/utf8）、预览画面比例、自动编译开关。

## 7. 对 M1–M4 计划的影响（增量）

1. **M1 不变**：`emitFunctionDef` 形态先作为模板接口预留，M1 只验证"调用点 + 反编译识别"的 round-trip；函数定义体生成在 M3 与资源管理器一起落地。
2. **M3 增补**：资源管理器（可编辑三张表）+ 新建工程向导（选底座游戏）。
3. **M4 增补**：剧本文本视图（只读投影）+ 时间线投影 + raw 只读占位块渲染。
4. **验收口径不变**：仍以模板覆盖 95% 剧情节点、raw 兜底 5% 为基线；新增"资源表可编辑 + 新角色可生成 SPEAK 函数"作为 M3 验收项。

---

## 8. 已确认的决策（最终）

1. **UI 主题**：深色（默认）+ 浅色两套主题，通过设置界面切换；两套共享同一 token 体系，均遵循 `quiet precision`。
2. **界面语言**：中文。
3. **底座游戏机制**：新建工程必须选一个底座游戏（首个支持 sakura），继承其函数库与 syscall 导入表。
4. **设置界面**：集中管理编辑器偏好（主题/语言/默认 NLS/预览比例/自动编译开关）。
