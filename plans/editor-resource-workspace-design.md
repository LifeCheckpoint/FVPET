# 编辑器 + 资源工作台综合体 —— 双界面架构设计

> 文档定位：响应「这不只是编辑器，而是编辑器 + 资源管理器综合体」的定位调整。把产品拆成两个独立区分的界面——**剧情编辑器**与**资源工作台**，并设计资源导入（含 hzc/nvsg 解包、批量）与联动机制。本文档是后续实现的架构依据。

---

## 1. 定位与原则

1. **综合体定位**：产品 = 剧情编辑器 + 资源工作台，二者平级、可随时切换，但共享同一份工程数据（`EditorState.resources`）。
2. **资源工作台是资源的唯一来源**：所有角色/背景/音频的增删改、导入、批量操作都发生在资源工作台；剧情编辑器只「引用」。
3. **所见即所得不依赖底座**：编辑器预览层的立绘/背景/音频直接消费工作台导入的图片/音频（data URL），与真实引擎的 `chaNum`/编号解耦。
4. **真实引擎层渐进**：hzc/nvsg 解包先服务于「预览 + 缩略图」，真实引擎的资源映射（`chaNum`）作为独立后续。

## 2. 双界面架构

### 2.1 顶层视图切换

现有 [`AppShell`](hcb-editor/packages/ui/src/components/AppShell.tsx:27) 是「顶栏 + 三栏画布 + 右侧信息栏 + 模态资源管理器」。调整为：

```text
┌─ 顶栏：模式切换 [剧情编辑器] [资源工作台] ─ 撤销/重做/保存/导出 ─┐
│                                                                      │
│  剧情编辑器（现有三栏）          资源工作台（全屏）                    │
│  左=调色板 中=画布 右=预览/属性   左=资源分类导航 右=资源网格/详情/预览 │
└──────────────────────────────────────────────────────────────────────┘
```

- 顶栏两个主 Tab 切换视图，`useState<'editor' | 'workspace'>`。
- 资源管理器从「模态对话框」升级为「顶层工作台视图」（全屏、可驻留）。

### 2.2 职责边界

| 界面 | 职责 | 不做什么 |
|---|---|---|
| 剧情编辑器 | 画流程图、编辑节点、连控制流、实时预览、导出 | 不直接增删资源、不导入图片 |
| 资源工作台 | 角色/背景/音频的增删改、单图/批量导入、hzc/nvsg 解包、图片↔表情分配、试听 | 不编辑剧情节点 |

## 3. 资源工作台设计

### 3.1 布局

```text
资源工作台
├── 左侧：分类导航（角色 / 背景 / 音频 / 导入队列）
└── 右侧：
    ├── 工具栏：导入按钮（单文件 / 文件夹 / hzc·bin 解包 / 拖拽）
    ├── 资源网格（卡片流，缩略图 + 名称 + 类型徽章 + 选中态）
    └── 详情/批量面板（选中项编辑；多选时批量改名/分类/分配）
```

### 3.2 角色工作区（解决「内置 vs 自定义」「双导入入口」）

- 统一列表：内置角色（`builtin: true`，预置自底座）+ 自定义角色。
- 每个角色卡 = 名字 + 立绘集（`pose/costume/face → 图`）+ speakFn 徽章（内置/自动）。
- **唯一导入入口**：角色卡内「导入立绘」——可单张，也可批量（多选文件按顺序成为 `(0,0,0)`, `(0,0,1)`… 的表情，或拖拽到某个表情槽）。
- 批量分配：选中多张图 → 一键「按序号填入表情集」/「指定 pose/costume/face 前缀」。

### 3.3 导入形式（多态）

| 形式 | 输入 | 行为 |
|---|---|---|
| 单文件 | 1 张图 / 1 段音频 | 填入当前选中资源 |
| 多文件 | N 张图 | 按文件名/顺序批量建角色或填表情集 |
| 文件夹 | 目录 | 递归扫描图片/音频，按子目录名建角色、文件名建表情 |
| hzc/nvsg 解包 | `.hzc1` 或 `.bin` 包 | 解出 PNG/WebP 缩略图 → 进入导入队列，再分配 |
| 拖拽 | 文件/文件夹 | 同多文件/文件夹 |

### 3.4 导入队列

- 解包/批量产生的资源先进入「导入队列」（未提交状态），支持预览、勾选、改名、批量分类，最后「确认导入」一次性写入 `resources`（一条 undo 步）。
- 避免大文件夹导入产生几百条不可撤销的散落命令。

## 4. 联动机制

1. **统一资源仓库**：`EditorState.resources` 是唯一事实来源，两个界面共享（同一个 store）。
2. **节点快速选资源**：
   - `speak.speaker` / `bsset.character` / `bgset.background` / `audio` 的编号，全部从 `resources` 生成候选（搜索式下拉，而非裸 `<datalist>`）。
   - 下拉里标注「内置 / 自定义」徽章，让来源一目了然。
3. **反向定位**：资源工作台里选中某角色 → 可「查看引用它的节点」→ 跳转回剧情编辑器并高亮。
4. **实时预览联动**：剧情编辑器预览直接读工作台导入的 data URL（已通过 `buildPreviewScript` 打通立绘/背景）。
5. **跨界面跳转**：顶栏 Tab 切换保留各自滚动/选中状态，不重建。

## 5. hzc / nvsg / bin 技术事实（已调研）

- **`.hzc1` 单图容器**（[`generate_assets.py`](.reference_repo/rfvp/win95_painter_demo/generate_assets.py:56)）：
  ```
  [4s "hzc1"][u32 original_len][u32 header_len=32]
  [4s "NVSG"][8×u16: unknown,type,w,h,offx,offy,u,v][3×u32: entry_count,unknown,unknown]
  [zlib 压缩的像素（BGRA premultiplied alpha）]
  ```
- **`.bin` 资源包**（[`vfs.rs`](.reference_repo/rfvp/crates/rfvp/src/subsystem/resources/vfs.rs:434)）：
  ```
  [u32 file_count][u32 filename_table_size]
  file_count × [u32 name_off][u32 data_off][u32 data_size]
  filename table（NUL 结尾字符串，按 nls 解码）
  ```
  即「文件名 → 数据块」的归档；`data_off/data_size` 指向的文件内容往往是 `.hzc1` 图片。
- **引擎解码**：Rust 侧 [`texture.rs`](.reference_repo/rfvp/crates/rfvp/src/subsystem/resources/texture.rs:53) 已实现 `hzc1/nvsg` 解码（zlib 解压 + BGRA premultiplied）；VFS 的 `parse` 已实现 `.bin` 包枚举。
- **TS 侧需要**：用 `node:zlib` / `DecompressionStream` 复刻 hzc1/nvsg 解码（浏览器可用），产出 PNG/WebP data URL；`.bin` 包解析用于「解包 → 缩略图浏览 → 选择性导入」。

## 6. 实现路线（分阶段）

### 阶段一：双界面骨架（纯 ui，无外部依赖）
1. [`AppShell`](hcb-editor/packages/ui/src/components/AppShell.tsx:27) 加 `'editor' | 'workspace'` 顶层切换；资源管理器从 modal 改为全屏工作台视图。
2. 左侧分类导航 + 右侧资源网格，保留现有三表卡片逻辑。

### 阶段二：统一角色模型（依赖上一份 `character-resource-design.md`）
3. `createProject` 预置内置角色；资源模型加 `builtin/chaNum`、移除单 `image`；单一「立绘集」入口。
4. 节点属性面板候选改为「搜索式下拉 + 内置/自定义徽章」。

### 阶段三：hzc/nvsg/bin 导入（TS 解码）
5. 新模块 `packages/ui/src/resources/hzc.ts`：解码 `.hzc1`（zlib + BGRA→RGBA）→ data URL；解析 `.bin` 包枚举。
6. 工作台「解包导入」：选 `.hzc1`/`.bin` → 缩略图预览 → 勾选导入。
7. 批量导入：多文件/文件夹/拖拽 + 导入队列 + 批量分配表情。

### 阶段四：联动增强
8. 资源「查看引用」反向定位；预览实时读工作台资源（已部分打通）。

## 7. 需要拍板的决策点

- **W1 双界面是「顶栏 Tab 切换」还是「侧边抽屉 + 主区」？** 建议顶栏两个主 Tab（更符合「两个独立区分的界面」）。
- **W2 hzc/bin 解包后，图片以 data URL 存工程，还是落盘到工程目录？** 建议：小图 data URL 内嵌（现架构），大图可后续落盘（需工程文件改为目录）。
- **W3 音频批量导入后，`audio` 节点如何引用？** 沿用「资源表编号」，工作台导入时自动分配编号，节点从资源表选。
- **W4 内置角色预置后，能否被批量导入的立绘覆盖？** 建议：允许（内置身份只锁定 `speakFn`，立绘可自由覆盖）。
